The Feature board on a phone

The Feature board is the sprint Taskboard's grid for one Feature: a row per story or bug, a column per task state, tasks as cards. A phone can't fit that grid. At 900px and below it works like the SHIP-719 boards: one task state a page in a sideways pager, with every story as a lane on every page. Tasks move through a ⋯ action sheet, or a long press and drag (to another story, or to the screen's edge for another state). Closed stories are one line each, as on desktop. The phones below are the reference screen (../screens/feature-board.html) at 390 × 844, made by screenshots.sh; open it in a window narrower than 900px to try it.

Three ways to fit it (D1: state pager)

The grid has two axes, stories and states. A phone can only show one of them at a time. The question is which one the page is about.

First recommendation

Story list

  • Reads like the page's job: how far along is each story of this Feature.
  • A story's tasks stay together; most stories have 1–5 tasks, so it stays short.
  • No sideways scroll, so no change to SHIP-805 rule 7. On a tablet the state groups sit side by side, a small board per story.
  • You don't see a whole column (“everything In review”) at once; Filter and People help.
  • Looks different from the SHIP-719 boards' pager.
Chosen 7 Nov · drawn below

State pager (as SHIP-719)

  • Same pattern as the Stories, Features and Epics boards (SHIP-719).
  • A whole column at a glance.
  • A story's tasks are split over four pages; its card, state and progress repeat as a lane header on every page.
  • Needs SHIP-719's rule 7 change (pager scrolls sideways); made 7 Nov for the boards.
  • With every lane on every page (D4) the stories line up page to page.
Alternative

The grid in its own sideways box

  • Least to build: today's grid with a narrower story column.
  • One and a half columns visible; titles cut to a few words.
  • The box scrolls both ways inside a page that scrolls: easy to get stuck.
  • Breaks SHIP-805 rule 7.

Acceptance criteria

With the decisions above; the same list is on SHIP-722.

  1. At 390 × 844 the Feature board has no page-level sideways scroll, in both themes, for a leaf Feature, a parent Feature and grouped by People. Only the state pager and the state chips scroll sideways, each in its own box. Above 900px nothing changes.
  2. At 900px and below one task state shows at a time with the next one peeking; swiping snaps to a state; the state chips show each state's task count (matching the filter) and turn to that state when tapped.
  3. Every open story or bug (or person, grouped by People) is a lane on every page, in the same order, showing “None” when it has no task in that state. Closed stories show as one-line lanes in backlog order, as on desktop.
  4. Every task can be moved on a touch screen: ⋯ opens its action sheet (Move to a state, another story, Assignee, Open); a long press lifts it to drag to another lane or, held at the screen's edge, to another state. Both behave as the same drop on desktop (auto-assign on In progress, never changes the sprint), and the pager stays on the page you were reading.
  5. Tapping a task opens the item modal full screen; closing it returns to the same page.
  6. The toolbar is one row (Stories | People, Filter (n), ⋯, + Add); Filter, ⋯ More and the task's sheets are built on SHIP-713's Sheet.
  7. Collapsing a story or a Feature band, the story's state select, + Task and + Add work as on desktop, at 32px or more.
  8. Page screenshots at 390 × 844 in both themes next to the desktop ones: feature-board, feature-board-active, feature-board-parent, feature-board-people, feature-board-task-actions.
  9. Analytics: work_item.moved from FeatureBoard.Move carries method (drag, touch drag, keyboard, sheet) next to the shared viewport, so we can compare task moves per Feature board view, week by week, on phones against desktop, before and after this ships.
