# Device check: voice on a Galaxy S22, a Galaxy S24 and an iPhone

A script for Joel to run by hand on three phones with a development build. Each step says what should happen. Tick the box when it does; write a time or a note where there is a gap. Anything that doesn't match goes in the results table at the end (section 10), and the table goes in a comment on SHIP-916.

Nothing here is a measured result. The times are targets, and the model choices follow the rules in the app today. The phone numbers come from this run.

**Voice is wired into the app** (SHIP-1197): it builds the speech and command engines at start-up, mounts the ready coach mark, the first-result sheet, the "from setup" tip, the voice change row and the voice-send-failed banner, and registers each screen's voice commands. Build from a branch that has it: `git log --oneline origin/feat/916-phone-app | grep "SHIP-1197.*Mount"`. The app needs a development build; Expo Go can't run it. A step that needs something a report says isn't built says **Not built** and is not a failure.

**Voice is input only.** Nothing in the app reads anything aloud. If a step ever makes the phone speak, play a sound or narrate, that is a bug: write it down.

## 0. Before you start

### The build

EAS isn't set up, so you build on your own machine and install over USB. From `src/ShipLean.Mobile`, after `cd .. && pnpm install` (once):

1. `npx expo prebuild`. It writes `android/` and `ios/` (gitignored) and rewrites the `android` and `ios` scripts in `package.json`: don't commit that change.
2. Android: turn on USB debugging, plug the phone in, run `npx expo run:android --device`. This builds a debug APK and installs it. It needs the Android SDK and JDK 17.
3. iPhone: plug it in, trust the computer, turn on Developer Mode (Settings › Privacy & Security), run `npx expo run:ios --device`. It needs Xcode and a signing team: pick your personal team when asked.
4. Metro (`pnpm start`) serves the JavaScript to a development build, so keep it running and the phone on the same network as your machine. A development build is not Expo Go: Expo Go has none of the native voice code and doesn't register the `shiplean://` sign-in redirect.

**The iPhone memory entitlement.** `app.json` sets `com.apple.developer.kernel.increased-memory-limit` for every build, development builds included. A free personal team can't sign that entitlement: if Xcode refuses ("Personal development teams do not support the Increased Memory Limit capability"), use a paid team, or remove the entitlement for this run and write it down in the results: without it iOS gives the app less memory and the 1.7B model may be closed by the system.

### The server

A phone can't reach `LocalHost`: it binds loopback only and has no switch for `0.0.0.0` yet. Use one of these instead, and type its address into the app's Server field:

- **The hosted server**, `https://prod.shiplean.app` (prefilled). Sign in with your own account. A change you make in this script goes to real data: use a throwaway project, or the ones named in section 3 that you can afford to change.
- **A server on your LAN** you start with the address bound to `0.0.0.0`, reachable at `http://<LAN IP>:<port>` and with the port open in the firewall. Plain `http` works in a development build (iOS allows local networking; debug Android builds allow cleartext).

The seeded data the commands in section 3 name (SHIP-906, SHIP-907, SHIP-742, SHIP-743, Priya Shah, Tom Okafor) comes from the dev seed: a LAN server with that seed is the safest place for sections 3 to 5. Sign in as `tom@shiplean.local` to see the Inbox's asks (`tom-dev-password`: see `src/ShipLean.TestSupport/SeedIds.cs`). On any other server, say the words for items you have and note the difference.

An identity-proxy server isn't supported: the app says so at sign-in.

### What Auto should pick

Auto goes by the memory the phone reports. The app shows the memory "as sold" (rounded up: 11.2 GB shows as 12 GB).

| Phone                             | Reports about | Auto picks | Qwen3 4B                                                 |
| --------------------------------- | ------------- | ---------- | -------------------------------------------------------- |
| Galaxy S24 (12 GB class)          | 11 GB or more | 4B         | Fine                                                     |
| Galaxy S22 (8 GB class)           | 7 to 8 GB     | 1.7B       | Can be picked, with a warning                            |
| iPhone 15 (6 GB)                  | about 6 GB    | 1.7B       | Greyed out: "Needs 8 GB of memory. This phone has 6 GB." |
| iPhone 16 Pro (8 GB)              | 7 to 8 GB     | 1.7B       | Can be picked, with a warning                            |
| 4 GB class (reports 4 GB or less) |               | Off        | Voice is off; everything else in the app works           |

Auto picks 4B only at 11 GB reported or more. The memory check before the command model loads counts half of the phone's reported memory as the app's share (`APP_SHARE` = 0.5), which is a first guess and is what this run calibrates (see section 8).

Expected: on the S22 (about 7.4 GB reported) the app may use about 3.7 GB, and 4B needs about 3.4 GB, so the memory check lets 4B load and the warning is about speed and the system closing the app, not the check. A 6 GB iPhone gets about 2.75 GB, enough for 1.7B only. If the check refuses a model these numbers allow, that is a finding.

- [ ] Write down each phone's model and its sold and reported memory in section 10 before you change anything. If Auto picks something other than the table, that is the first finding.

## 3. Each screen's top voice commands

- **Apply** sends at once. A toast offers **Undo** for 8 seconds after the send. A tap's own Undo holds for 5 seconds before it sends; a voice or typed change is sent first and undone after.

- Note words are copied word for word from what you said, never reworded.
